Oriel NFT does not provide models, accounts, or inference credits. When self-hosted, projects and images stay on your own machine by default. The developer does not proxy model requests or pay upstream inference costs.

> **Security:** The application has no user login or tenant isolation. It binds to localhost by default and is intended for local or trusted-network use. Do not expose its application port directly to the public internet. Any hosted instance must enforce authentication at a reverse proxy (for example, Cloudflare Access, a VPN, or equivalent). The application does not provide that protection itself. A public demo should use a separate, resettable environment that does not retain users' API keys.

## Quick start

Requirements: Python 3.12+ and Node.js 22.

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
cd web && npm ci && npm run build && cd ..
python -m server
```

Open <http://127.0.0.1:8787>. Without a provider, use **Offline sample** to try traits, composition, rarity, and export. Its sample layers are drawn programmatically, not generated by a model.

For hot-reload UI development, run `python -m server` and, in another terminal, `cd web && npm run dev`. The UI is at <http://127.0.0.1:5173> and proxies API requests to port 8787.

## Workflow

1. Create a collection and choose a subject-change mode. The UI explains each mode beside the control.
2. Upload a reference image. It may depict a character, object, photograph, or abstract art; analyze it before deciding what to make.
3. Generate three distinct art directions, refine one in natural language, and lock a master image.
4. Confirm the style contract and plan traits. Backgrounds, patches, and accessories can be layered; structural changes such as clothing or pose use complete base images. After locking, create a new project to change the master.
5. Generate and review assets. Re-review assets after changing the style contract. Regenerate an asset when its trait description, layer method, or position changes.
6. In **Collection**, generate up to eight trial images. Check subject identity, lighting, and layer edges, then approve the trial before full generation. Changes to assets, rules, or subject cutout require a new approval.
7. Browse results, reroll individual items, edit traits, and download a ZIP. It contains PNGs in `images/`, per-item JSON in `metadata/`, and rarity statistics and an inventory in `summary/`.

Generation selects weighted legal combinations from reviewed assets. If there are too few valid combinations or an exact pixel duplicate is detected, the batch stops and the existing collection remains available. Visually similar images are flagged for human review.

On-chain minting, wallets, and marketplaces are outside the current scope. Exported metadata can be used with a publishing workflow of your choice.

## Providers

In **Provider settings**, configure an OpenAI-compatible endpoint:

- **Base URL:** commonly ends in `/v1`.
- **API key:** optional for local endpoints without authentication. Saved keys are encrypted with the deployment-local `data/secret.key`; the UI only reports whether a key is saved. When changing the Base URL, supply the key for the new endpoint.
- **Models:** select separate vision, planning, image-generation, and reference-editing models. If the edit model is blank, the image model is used.
- **Image API:** choose the OpenAI Images API or a chat endpoint that accepts and returns images.

Discover models through `/models` or enter model IDs manually. Strict preservation mode, language refinement, model-based cutout, and asset generation require reference-image editing. For other direction exploration, text-only generation may be used when the edit endpoint is unavailable; the UI indicates whether the reference was sent. Remote calls send images to the selected provider, which may charge for usage.

## Skills

Built-in skills live in `skills/*.json`. Each defines consistency constraints, three pre-lock directions, and which traits can be layered versus require a full-image redraw. Once a master is locked, the collection follows that single style contract rather than mixing the three exploration images.

Community skills use the same schema. Files without consistency constraints are not loaded.

## Docker

```bash
docker compose up --build
```

The `oriel-data` volume stores the database, images, and `secret.key`. If the key is lost, saved provider keys cannot be decrypted and must be entered again. The container listens on `0.0.0.0:8787`, while Compose binds it to host `127.0.0.1:8787`. Do not publish the container port directly; enforce authentication at a reverse proxy or Cloudflare Access before hosting it online.

## Tests

```bash
pip install -r requirements.txt
pytest
```

Tests cover insufficient combinations, green-screen cutout, trial approval gating, preserving an existing collection on failure, reference-edit fallback rules, secret non-disclosure, and validation of PNGs, metadata, and summary files for a 100-item offline sample.

## Data and privacy

The default data directory is the project-local `data/`; set `ORIEL_DATA` to use another location. Export ZIPs contain images, metadata, rarity statistics, and a manifest without provider credentials. Images sent to a remote model are subject to that provider's policies and retention terms.

The UI uses Fraunces and Outfit; their license texts are in `web/public/fonts/`.
